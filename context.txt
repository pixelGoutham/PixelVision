# PixelVision: Gemma 4 Set-of-Mark Workbench

## What It Does
PixelVision is a React + TypeScript + Vite application that serves as an AI-powered UI/UX auditing workbench. It leverages Google's Gemma 4 multimodal AI model (31B/26B parameters) to analyze web pages for visual and layout issues using the Set-of-Mark technique. The application allows users to:
- Import live website URLs or use preset demo cases
- Visualize DOM elements with Set-of-Mark badges
- Run multimodal audits against product specifications
- Receive AI-generated violation reports and suggested remediation patches
- Apply AI-suggested fixes directly to the code editors

## The Arc (Purpose & Vision)
PixelVision was created to bridge the gap between advanced AI capabilities and practical UI/UX development workflows. The core vision is to:
1. Make cutting-edge multimodal AI (Gemma 4) accessible to frontend developers and designers
2. Provide objective, AI-driven feedback on visual design quality
3. Automate detection of common UI issues like overlapping elements, inadequate touch targets, and layout breaks
4. Close the loop between AI analysis and implementation by providing actionable, editable patches
5. Serve as a verification engine that ensures UIs meet specified product requirements before shipping
6. Explore how specialized AI models can be integrated into creative workflows to augment human judgment rather than replace it

## The Why (Motivation & Problem Space)
Modern web development faces several challenges that PixelVision addresses:
- **Subjective UI Reviews**: Design critiques often rely on personal preference rather than objective criteria
- **Missed Visual Issues**: Overlapping elements, insufficient touch targets, and layout breaks slip through manual QA
- **Inconsistent Implementation**: Design specs aren't always faithfully translated to code
- **Accessibility Oversights**: Touch target sizing and visual hierarchy issues affect usability
- **Slow Feedback Cycles**: Manual review processes delay issue detection and resolution

PixelVision solves these by:
- Using Gemma 4's multimodal reasoning to evaluate UIs against explicit product specifications
- Applying the Set-of-Mark technique to provide spatial context to the AI model
- Generating specific, actionable feedback with visual explanations
- Offering one-click application of AI-suggested fixes
- Enabling rapid iteration between design, implementation, and verification

## The How (Technical Implementation)

### Architecture Overview
PixelVision follows a client-side only architecture with simulated backend APIs:
- **Frontend**: React 18 + TypeScript + Vite
- **State Management**: React hooks (useState, useCallback, useEffect)
- **UI Components**: Custom components with Lucide React icons
- **Styling**: Tailwind CSS with customizations (now enhanced with Apple WWDC Fluid Interface principles)
- **AI Integration**: Simulated API endpoints (`/api/fetch-url`, `/api/audit`) that would connect to Gemma 4 in production

### Core Technologies & Techniques

#### 1. Set-of-Mark Visualization
The application implements Google's Set-of-Mark technique:
- DOM elements are scanned for interactive and visual candidates (buttons, links, headers, etc.)
- Each element receives a unique badge ID and visual bounding box
- Badges are rendered as red circles with white numbers in an overlay
- The marked visualization is captured as an image and sent to Gemma 4 alongside DOM telemetry

#### 2. Multimodal AI Pipeline
The auditing process follows this flow:
1. User provides HTML/CSS (via URL import, preset selection, or manual entry)
2. SandboxRenderer creates an iframe with the provided code
3. Set-of-Mark script runs in the iframe, generating:
   - Base64 PNG image of the marked visualization
   - DOM telemetry array (element properties, text snippets, positions)
4. User's product specification is combined with the image and telemetry
5. Data is sent to the `/api/audit` endpoint (simulated)
6. Gemma 4 analyzes the multimodal input and returns:
   - Pass/fail verdict
   - Human-readable summary
   - Detailed violations (type, severity, affected badge IDs)
   - Suggested remediation patch (HTML/CSS changes with explanation)
7. Results are displayed in the verification report panel

#### 3. Key Components

**App.tsx**: Main application controller managing state for:
- Code editors (HTML/CSS)
- Product specification text
- Live URL importing
- Demo preset selection
- Audit execution and result handling
- Patch application
- Cache management

**SandboxRenderer.tsx**: Responsible for:
- Rendering HTML/CSS in an isolated iframe
- Injecting Set-of-Mark badge generation script
- Handling cross-origin image capture with fallback strategies:
  * Tier 1: html-to-image with skipFonts + imagePlaceholder
  * Tier 2: Filtering cross-origin media elements
  * Tier 3: Native Canvas Set-of-Mark renderer (guaranteed fallback)
- **NEW**: Enhanced with Apple WWDC Fluid Interface design principles:
  - Pointer-down response (scale(0.97) on active states)
  - Optical typography with negative letter spacing
  - Translucent materials with backdrop-filter effects
  - Improved reduced motion support
  - Apple-style translucent stage toolbar
  - Enhanced image preview with backdrop blur
- Communicating telemetry and captured image back to parent via postMessage

**gemmaClient.ts**: Handles AI interaction:
- SHA-256 hashing of inputs for caching
- IndexedDB localforage cache for audit results (now v4)
- Request/response formatting for the simulated audit API
- Error handling and cache management
- **NEW**: Integrated Apple HIG (Human Interface Guidelines) & Fluid Interface principles:
  - All audit evaluations now reference Apple HIG & Fluid Interface specifications
  - Violation descriptions include specific Apple guideline references (§1 Pointer-down, §7 Spatial Consistency, §10 Touch Target, etc.)
  - Suggested patches include Apple WWDC Fluid CSS for automatic compliance
  - Deterministic demo mode enhanced with Apple design principles
