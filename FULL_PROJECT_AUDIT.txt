# PixelVision: Gemma 4 Set-of-Mark Workbench - FULL PROJECT AUDIT

## PROJECT OVERVIEW

PixelVision is an innovative AI-powered UI/UX auditing and verification workbench that combines Google's Set-of-Mark (SoM) visual prompting technique with Gemma 4 (31B/26B) multimodal reasoning to audit live webpages against explicit product specifications, detect visual/layout issues, and apply AI-suggested fixes in one click.

Built as a React 18 + TypeScript + Vite application, PixelVision serves as a Hacktoberfest Hack Day Bengaluru 2026 submission for:
- **Primary Track:** Best Use of Gemma 4 (Multimodal AI Intelligence)
- **Open-Source Alignment:** Best Open-Source AI Project (Trustworthy and Verifiable AI)

## CORE PURPOSE AND VISION

PixelVision was created to bridge the gap between advanced AI capabilities and practical UI/UX development workflows. The core vision is to:

1. Make cutting-edge multimodal AI (Gemma 4) accessible to frontend developers and designers
2. Provide objective, AI-driven feedback on visual design quality
3. Automate detection of common UI issues like overlapping elements, inadequate touch targets, and layout breaks
4. Close the loop between AI analysis and implementation by providing actionable, editable patches
5. Serve as a verification engine that ensures UIs meet specified product requirements before shipping
6. Explore how specialized AI models can be integrated into creative workflows to augment human judgment rather than replace it

## PROBLEM STATEMENT

Modern web development faces several challenges that PixelVision addresses:

- **Subjective UI Reviews**: Design critiques often rely on personal preference rather than objective criteria
- **Missed Visual Issues**: Overlapping elements, insufficient touch targets, and layout breaks slip through manual QA
- **Inconsistent Implementation**: Design specs aren't always faithfully translated to code
- **Accessibility Oversights**: Touch target sizing and visual hierarchy issues affect usability
- **Slow Feedback Cycles**: Manual review processes delay issue detection and resolution

## TECHNICAL SOLUTION

PixelVision solves these problems by:

1. Using Gemma 4's multimodal reasoning to evaluate UIs against explicit product specifications
2. Applying the Set-of-Mark technique to provide spatial context to the AI model
3. Generating specific, actionable feedback with visual explanations
4. Offering one-click application of AI-suggested fixes
5. Enabling rapid iteration between design, implementation, and verification

## CORE COMPONENTS DETAIL

### 1. App.tsx (Main Application)
The central controller managing:
- State for HTML/CSS editors, product specification, live URL input
- Demo preset selection and management with live website fetching
- Audit execution state and results handling
- Patch application functionality with one-click apply
- Cache management controls for IndexedDB operations
- UI layout with collapsible sidebar, main content area, and verification panels

Key Features in App.tsx:
- Live URL importing that harvests actual DOM & CSS from live websites
- Demo presets for Apple.com hero section and Pixel Blast course landing page
- Bug simulation capabilities to test self-healing remediation
- Reset functionality to restore clean website state
- Deterministic demo mode to prevent API 503 errors during presentations
- Visual feedback system with color-coded results and iconography

### 2. SandboxRenderer.tsx (Set-of-Mark Implementation)
Responsible for the core Set-of-Mark technique:

Features:
- Creates isolated iframes for rendering HTML/CSS securely
- Implements three-tier image capture strategy for CORS resilience:
  * Tier 1: html-to-image with skipFonts + imagePlaceholder
  * Tier 2: Filtering cross-origin media elements
  * Tier 3: Native Canvas Set-of-Mark renderer (guaranteed fallback)
- Injects Set-of-Mark badge generation script that:
  * Scans DOM for interactive and visual candidates (buttons, links, headers, etc.)
  * Assigns unique badge IDs and creates visual bounding boxes
  * Renders badges as red circles with white numbers in overlay
  * Generates structured DOM telemetry (element properties, text snippets, positions)
- Handles viewport states (mobile/tablet/desktop) with responsive scaling
- Communicates telemetry and captured images via postMessage to parent component
- Provides UI controls for viewport switching, snapshot preview, and re-indexing

### 3. gemmaClient.ts (AI Integration Layer)
Handles all AI-related functionality:

Capabilities:
- SHA-256 hashing for cache key generation to prevent redundant API calls
- IndexedDB caching via localforage for audit results (PixelVisionWorkbench store)
- Deterministic demo audit fallback for reliable presentations (0% chance of 503 errors)
- Real API call simulation to /api/audit endpoint with retry logic
- Error handling and graceful degradation when API is unavailable
- Composite payload hashing for efficient cache lookups
- Automatic cache population on successful API calls

## DATA FLOW DETAIL

1. **Input Phase**: User provides HTML/CSS via:
   - Live URL import (fetches actual website)
   - Demo preset selection (Apple.com or Pixel Blast)
   - Manual code entry in editors

2. **Rendering Phase**:
   - HTML/CSS sent to SandboxRenderer component
   - Component creates iframe with provided code
   - Sets up base tag for proper asset resolution when applicable
   - Applies CSS and sanitizes problematic elements (scripts, iframes, etc.)

3. **Set-of-Mark Generation** (in iframe):
   - Waits for page stabilization (scrolling, font loading, etc.)
   - Scans for interactive/semantic elements (buttons, links, headers, images, etc.)
   - Filters out hidden/offscreen elements and duplicates
   - Creates visual bounding boxes and red numbered badges
   - Generates DOM telemetry array with element properties
   - Sends telemetry + marked image to parent via postMessage

4. **AI Analysis Phase**:
   - Parent component receives marked image (base64) and DOM telemetry
   - Combines with user-provided product specification
   - Computes SHA-256 hash for cache lookup
   - Either returns cached result or calls /api/audit endpoint
   - Endpoint would call Gemma 4 in production (currently simulated)
   - Returns structured audit results with violations and suggested patches

5. **Result Presentation Phase**:
   - Displays verification report with pass/fail status
   - Shows violations with badge references and severity levels
   - Presents suggested remediation patch with explanation
   - Offers one-click application of fixes to code editors
   - Updates UI with visual feedback (checkmark/alert triangle)

## KEY INNOVATIONS

### Set-of-Mark Technique Implementation
Unlike traditional approaches that ask AI to guess pixel coordinates from screenshots, PixelVision:
- Deterministically scans the live DOM inside an isolated sandbox
- Injects numbered red Set-of-Mark badges with exact bounding boxes
- Pairs the marked screenshot with structured DOM telemetry
- Provides both visual canvas and structural data to Gemma 4
- Enables badge-referenced violation reports for precise debugging

### Multimodal Auditing Pipeline
The application combines:
- Visual analysis: The Set-of-Mark marked screenshot
- Structural analysis: DOM telemetry with element properties and positions
- Contextual analysis: User-provided product specification
- This triple-input approach enables Gemma 4 to make informed decisions about:
  - Visual overlapping between elements
  - Touch target adequacy (44px minimum)
  - Layout breaks and clipping issues
  - Typography rhythm and spacing consistency
  - Visual hierarchy maintenance

### Self-Healing Remediation System
When violations are detected:
- Gemma 4 generates specific HTML/CSS patches to fix issues
- Patches include detailed explanations of what was wrong and how the fix helps
- One-click application applies patches directly to code editors
- System preserves clean website state to enable reset functionality
- Post-patch verification confirms fixes resolve detected issues

### Caching and Performance Optimization
- SHA-256 hashing of inputs for deterministic cache keys
- IndexedDB storage via localforage for persistent caching
- Deterministic demo mode eliminates API dependency for presentations
- Graceful fallback to simulated audits when API unavailable
- Cache busting mechanisms when code changes

## ARCHITECTURE DECISIONS RATIONALE

### Client-Side Only with Simulated Backend
Chosen for:
- Portability and ease of deployment (static hosting possible)
- Privacy protection (no user data leaves client browser)
- Demonstration clarity (all logic visible in source code)
- Reduced infrastructure complexity for hackathon submission
- Simulated APIs demonstrate production architecture without deployment overhead

### React 18 + TypeScript + Vite Stack
Selected for:
- Modern React features (concurrent rendering, automatic batching)
- Type safety preventing runtime errors in complex AI integration
- Fast development experience with Vite's instant server start
- Excellent developer experience with hot module replacement
- Strong ecosystem and community support

### Tailwind CSS Approach
Chosen for:
- Utility-first approach enabling rapid UI development
- Design system consistency through configurable constraints
- Excellent responsiveness with mobile-first breakpoint system
- Minimal CSS footprint through purging unused styles
- Easy customization and extension with custom CSS

### IndexedDB via localforage for Caching
Selected for:
- Persistent storage surviving browser refreshes and sessions
- Key-value interface perfect for hash-based cache lookups
- Asynchronous non-blocking API compatible with React
- Fallback mechanisms for older browser support
- No server dependency for offline functionality

### Three-Tier Image Capture Strategy
Implemented for:
- Maximum compatibility across different website structures
- Fallback gracefulness when primary methods fail
- CORS resilience for cross-origin resource loading
- Guaranteed functionality through synthetic canvas rendering
- Performance optimization by trying fastest methods first
